# MPS 赛道阶段性项目完成报表设计

## 目标

基于 2026-07-30 工作树中的最新计划、状态文档、标准 `run.json`、结果清单、
哈希绑定 manifest 和已生成图表，制作一份可离线打开、可追溯、可继续更新的
双层阶段性报表。首页供阶段评审快速阅读，后续区块保留技术证据和未完成门槛。

## 快照边界

- 截止日期：2026-07-30。
- 范围：`tracks/mps/` 的 LTRG 复现，以及 `tracks/mps/DMRG/` 中的二维
  VMCRG、Issue 28 Easy Goal、MPS/TT 辅助路线和三维自旋玻璃 Hard Goal。
- 只读取已经存在的结果，不启动新的数值计算、收敛扫描或集群作业。
- 报告状态不使用主观完成百分比，只使用 `已验证完成`、`部分完成`、
  `进行中`、`未完成` 和 `科学负结果`。
- `PROJECT_STATUS_AND_ROADMAP.md` 的 2026-07-27 结论只作为历史背景；
  2026-07-30 的 B4 状态和最新运行结果优先。

## 证据优先级

1. 哈希绑定的运行 manifest、selection、assessment 和标准 `run.json`。
2. 与结果同日更新的阶段状态文档。
3. 已记录的测试、语法、哈希复核和不可覆盖检查。
4. 计划、设计和资源预测；预测值不得写成运行结果。

每个重要结论都在报告中给出源文件路径。冲突时按上述顺序取值，并在正文中
说明旧状态文件已经被后续证据覆盖。

## 页面结构

报告固定为四部分：

1. `挑战与阶段摘要`：管理层摘要、项目背景、三条主线和总状态矩阵。
2. `工作流与证据体系`：模型/协议锁定、测试驱动、不可变产物、计算资源和
   科学门槛。
3. `运行结果`：LTRG、二维 VMCRG/Easy Goal、MPS/TT 辅助路线、三维 Hard
   Goal 的关键数值、结论和图表。
4. `阶段亮点与后续路线`：创新、阻塞项、下一阶段门槛、资源预览和成果索引。
