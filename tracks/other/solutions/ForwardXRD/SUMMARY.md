## 1. Challenge review and things to do

**The problem.** Recover an atomic crystal structure from its powder XRD pattern with chemical composition given, using a generative prior over crystal structures (CrystalFormer) rather than a from-scratch structure search.

**The challenge's proposed approach.** Sample candidate structures $X$ from CrystalFormer's prior $p(X)$
(space group discovered as the model's own first token, not given), score each against the measured pattern with a cosine-similarity reward $r(X)$, then fine-tune a variational distribution $q(X)$ by PPO to minimize $F = E[−r(X)] + τKL(q‖p)$ to increase the success rate of picking out the correct structure.

**To-dos**:

1. Build and validate the pattern-fit reward.
2. Implement $q(X)$ and sweep $\tau$ to see its effect.
3. Benchmark on held-out cases from SimXRD-4M ([arXiv:2406.15469](https://arxiv.org/abs/2406.15469)); report structure-match rate.
4. Test the workflow on experimental XRD patterns.

## 2. Our technical approach

```
measured pattern (2θ, I)                    SG (from systematic absences)
        │                                            │
        ▼                                            ▼
  [1] INDEX  ─── classical, SG-symmetry-constrained ─────┘
        │        
        ▼
  [1b] STANDARDIZE  (Gauss reduction / axis-setting fit)
        │
        ▼                                     
  [2] GENERATE  ◄── done by CrystalFormer, composition- and SG-conditioned 
        │           
        ▼
  [3] MLFF RELAX   done by MACE, coordinates only, cell fixed
        │
        ▼
  [4] RANK   EMD + non-negative Chebyshev background
        │
        ▼
  [5] REFINE   Wyckoff-site-symmetry-constrained DE, in the indexed cell
        │
        ▼
  candidate structure(s) → StructureMatcher against ground truth
```

The table below states the major changes against the originally proposed technical route:

|                 | proposed                   | built                                                        | why                                                   |
| --------------- | -------------------------- | ------------------------------------------------------------ | ----------------------------------------------------- |
| **reward**      | cosine similarity          | Earth Mover's Distance (EMD) + non-negative Chebyshev background | cosine **inverts** on noisy data (§3.2)               |
| **cell**        | generated by CrystalFormer | classically indexed from peak positions                      | fixed the cell 500–1600× better than the motif (§3.2) |
| **space group** | discovered as first token  | conditioned on, from systematic absences read from the XRD pattern | improved 67× on baddeleyite                           |
| **search**      | PPO optimising q(X)        | best-of-N + MLFF + deterministic refinement                  | not needed (§4)                                       |

## 3. Results

### 3.1 Structure recovery performance

**A smoke test succeeded for 7/7** hand-picked structures from the Materials Project, spanning five crystal systems:

(DoF = Degrees of Freedom of Wyckoff sites)

| target            | space group          | DoF  | cell error | rms vs truth |
| ----------------- | -------------------- | ---- | ---------- | ------------ |
| pyrite FeS₂       | Pa-3 (cubic)         | 1    | 0.003 %    | 0.0000       |
| rutile TiO₂       | P4₂/mnm (tetragonal) | 1    | 0.008 %    | 0.0001       |
| marcasite FeS₂    | Pnnm (orthorhombic)  | 2    | 0.014 %    | 0.0001       |
| quartz SiO₂       | P3₁21 (trigonal)     | 4    | 0.010 %    | 0.0001       |
| tenorite CuO      | C2/c (monoclinic)    | 1    | 0.012 %    | 0.0002       |
| baddeleyite ZrO₂  | P2₁/c (monoclinic)   | 9    | 0.006 %    | 0.0012       |
| perovskite CaTiO₃ | Pnma (orthorhombic)  | 7    | 0.019 %    | 0.0015       |

**MP.db test.** SimXRD-4M doesn't have usable ground truth for this task: its test split (`test_binxrd`, 200,630 rows) has no `cell` and `positions` recorded. 

Thus, we built a substitute straight from `MP.db` (MP-2024.1 thermodynamically stable structures used by SimXRD).

Success rate: **11/15** at the same strict tolerance, spanning cubic, orthorhombic, hexagonal, tetragonal, and monoclinic, 2–20 atoms, 0–18 free internal coordinates.

**Comparison against SmartCellSolver, an external baseline.** We analyzed 66 targets from SmartCellSolver's own published test set (arXiv:2605.24594, github.com/MaterSim/Ab-PXRD-Solver), using their real XRD pattern files.

| system             | solved/total number of samples | success rate |
| ------------------ | ------------------------------ | ------------ |
| cubic              | 12/12                          | 100.0 %      |
| hexagonal/trigonal | 7/11                           | 63.6 %       |
| tetragonal         | 4/12                           | 33.3 %       |
| orthorhombic       | 2/12                           | 16.7 %       |
| monoclinic         | 1/18                           | 5.6 %        |
| **overall**        | **26/65**                      | **40.0 %**   |

SmartCellSolver's own published criterion (Rietveld R² ≥ 0.95, χ² ≤ 0.12) reports success on 50/52 (96.2 %) of the identical targets. **However, their criterion does not measure the same thing as ours**. Their criterion is a *pattern fit*: does the simulated pattern from the proposed structure align with the observed one at R² ≥ 0.95? Nevertheless, our criterion requires the actual atoms to be in the actual places, a **stricter** bar focusing on the reality of the crystal structure.

## 4. Do we really need q(X)?

**The current pipeline contains no q(X) and we think reinforcement learning is probably not necessary**. We categorized representative, unfixed failures in our attempts so far:

- **16 were indexing failures** (bad cell), the majority traced to algorithmically fixable bugs that we are working on.
- **1 was a Wyckoff-refinement bug** (origin-choice mismatch).
- **19 were EMD criterion mistakes**.
- **1 was a structure-pattern mismatch** due to a labelling mistake in the dataset.

Based on the scanned samples so far, our observation is: **Constrained by the indexing information, it seems CrystalFormer has generated structure priors distinct enough in the "XRD-pattern space", as so far none of the mistakes are due to "wrong-but-plausible look-alikes". As such, q(X) is probably not necessary because for most of the failures we've now traced, fine-tuning the generator by RL would not fix them, since they were not due to pattern ambiguity.** In other words, just by fixing the classical algorithms in the workflow is expected to increase the current recovery rate sharply, and this is exactly the thing we are working on.

We also note that the scope of our tests is limited due to the shortage of time and laborious computation, so there might still be some challenging cases not yet discovered which may affect our conclusion.
