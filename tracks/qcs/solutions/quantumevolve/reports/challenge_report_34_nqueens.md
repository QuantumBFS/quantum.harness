# Challenge Report: #34 N-Queens Exact Counting

## Issue
**#34** — N-Queens 精确计数：计算 N×N 棋盘上放置 N 个互不攻击皇后的方案数 Q(N)。
进化目标是改进收缩策略（路径优化、分治、对称性分解等），使更大 N 可行。

种子策略：位掩码回溯（exact bitmask backtracking），对 N=8 仅需 1ms 给出 Q(8)=92。

## 种子分析

种子代码使用经典的位掩码回溯算法：
- 用三个整数 `columns`, `diag_left`, `diag_right` 的 bit 表示当前攻击线
- 每步选择最低可用 bit 放置皇后
- N=8 时搜索树仅 ~2000 节点，耗时 1ms

**关键观察**：N=8 对回溯太简单了（Q(8)=92, 1ms），种子直接 score=1.0。
进化需要在更大 N（如 N=12, Q(12)=14200）或效率指标上才有意义。

## evaluator 设计

两步验证架构：
1. `main.py` 候选代码 → `candidate_result.json`
2. `verify_nq.py` 用 OEIS A000170 参考值比对 Q(N)

评分：
- exact match（Q_candidate == Q_exact）→ score=1.0
- 近似（|log10(ratio)| < 1）→ score=0.5*(1−|log10(ratio)|)
- 错误 → score=0

## 成功原因（预期）
- 种子代码正确且高效——回溯算法对中小 N 几乎最优
- OEIS 参考值防止作弊——候选必须真正计算 Q(N)
- 位掩码实现已经是回溯的工程最优（无额外内存分配）

## 失败风险
1. **天花板效应**：N=8 种子已经 1ms/score=1.0，进化无提升空间
2. **大 N 难度跳跃**：N=14 (Q=365596) 需要分钟级，N=15 (Q=2279184) 需要小时级
   ——LLM 可能无法在代码大小限制内发明质的不同算法
3. **已知最优算法很难超越**：位掩码回溯 + 对称性剪枝已经是 N-Queens 计数的
   最佳实践，进一步改进需要非常规方法（如代数化、传递矩阵法）

## 反思与体会
- **简单问题的进化需要难度梯度**：evaluator 应该评估多个 N（如 N=8,10,12,14）
  并给出综合 score，而非单一 N=8——否则种子直接满分，进化没有梯度信号
- **N-Queens 是进化的好 benchmark 但不是好 target**：它太干净了——
  正确性是二值的（exact/not），效率差异主要体现在大 N，而大 N 超时
- **评估器改进方向**：score = Σ_N w(N) * (1 if exact) / time_normalized(N)，
  其中 N 从 8 到 14，权重随 N 递增——这样进化有动力改进大 N 效率
