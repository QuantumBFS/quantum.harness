# Harnessing Quantum 2026 培训仓库集成计划

> 2026-07-27 policy update: the entire `.training/` tree is now local-only and ignored by the main workspace repository. The workflow below remains the operating record for an already provisioned local training environment, but a fresh clone must provision its control scripts separately.

## 目标

在不破坏凝聚态个人工作空间的前提下，使用个人 fork 完成一周黑客松的复现、挑战、skill 改进和 Pull Request。培训仓库必须保留官方目录结构、完整 skills 和独立 Git 历史，同时允许将有长期价值的结果归档回个人工作空间。

## 已确认的官方要求

- 官方仓库：<https://github.com/QuantumBFS/quantum.harness>
- 个人 fork：<https://github.com/XeriChen/quantum.harness>
- 每组 1–3 人，使用一个 `group-<team-name>` 分支提交一个 PR。
- 小组分支从最新 `main` 创建。
- 官方流程要求运行 `make skills` 后使用 `/beginner-training` 完成环境自检和论文复现；本工作空间使用 `.training/bin/bootstrap-skills.sh` 等价初始化 skills，并处理当前 Ion 0.6.5 与上游锁文件的兼容问题。
- 挑战代码与 README 放入 `tracks/<track>/solutions/`。
- 生成数据和图片放入 `tracks/<track>/results/`，该目录不提交。
- PR 同时包含 harness 改进、挑战解答，以及由 `/challenge-report` 生成并发布在 PR 评论中的复现 prompt。
- 以第四天上午 PR 和 CI 全绿为内部截止；周四 20:00 之前只做最终修订。

## 仓库边界

```text
condensed-matter-workspace/
├── master                          # 长期科研工作空间
├── quantum.harness/                # 官方固定版本子模块，不写培训作业
├── data/processed/hackathon/       # 经筛选的长期成果归档
├── notes/                          # Obsidian 研究记录
└── .training/                      # 整体本机忽略的培训区
    ├── README.md                    # 本机使用说明
    ├── bin/                         # 本机初始化与启动脚本
    ├── repos/
    │   └── quantum.harness/         # 个人 fork 的干净 main 镜像
    ├── worktrees/
    │   └── group-<team-name>/       # 组队后再创建
    ├── tools/、xdg/                 # repo-local Ion、配置与缓存
    └── exports/                     # 临时成果交换区
```

`.training/` 的控制脚本与运行态现在统一保留在本机并由 `.gitignore` 排除，不再进入主仓库历史。现有环境可以继续使用这些脚本；新 clone 必须从独立备份或受信来源重新 provision 控制面，同时继续避免嵌套仓库、虚拟环境、训练结果或凭据被误提交。

## Remote 规范

个人 fork 的基准 clone 使用：

```text
origin    git@github.com:XeriChen/quantum.harness.git
upstream  git@github.com:QuantumBFS/quantum.harness.git
```

- `origin/main` 是个人 fork 的镜像分支。
- `upstream/main` 是创建小组分支和同步官方更新的唯一基线。
- 本地将 `upstream` 的 push URL 设为 `DISABLED`，避免误把提交推向官方仓库；正式贡献只通过 GitHub PR。
- 不修改主工作空间中 `quantum.harness/` 子模块的 remote。
- 不把个人 fork 写入主仓库 `.gitmodules`。

## 当前阶段：只完善基准 clone

当前允许完成：

1. 克隆个人 fork 到 `.training/repos/quantum.harness/`。
2. 添加并验证 `upstream`。
3. 将本地 `main` 快进到最新 `upstream/main`。
4. 同步 `origin/main`。
5. 检查官方本地 skills、Agent 入口和基础测试命令。

本地维护命令：

```bash
.training/bin/check-base.sh
.training/bin/sync-main.sh
.training/bin/bootstrap-skills.sh
```

`check-base.sh` 不访问网络；`sync-main.sh` 使用 `gh repo sync` 同步 GitHub fork，再只允许本地 fast-forward。

Ion 不安装到 home。它和远程 skills 使用下列本地路径：

```text
.training/tools/bin/ion
.training/xdg/data/ion/
.training/xdg/config/ion/
.training/xdg/cache/
```

当前 Ion 0.6.5 首次拉取 `sci-brain` 时没有正确执行旧版 `Ion.lock`，并会因为第三方 skill 验证警告而停止。`bootstrap-skills.sh` 在 `.training` 缓存中按 lock 修复提交、显式保留警告输出并恢复原锁文件，不修改 fork 的提交内容。

当前明确不做：

- **不创建字面名称 `group-<team-name>` 的占位分支。**
- **不在队名确定前创建任何 `group-*` 远程分支。**
- 不在基准 clone 中开发挑战代码。
- 不修改当前主工作空间的 `quantum.harness/` 子模块。
- 不安装所有重型数值栈。

## 组队后的分支与 worktree

队名确定后，将 `<team-name>` 替换成简短、全小写、用连字符连接的真实队名，并从工作空间根运行唯一初始化入口：

```bash
.training/bin/create-group-worktree.sh <真实队名>
```

该脚本会先安全同步 fork `main`，再从 `upstream/main` 创建并推送 `group-<team-name>`，最后为 worktree 初始化 repo-local skills。建立远程分支后，小组成员只在该分支协作。共享分支开始使用后，未经全组确认不 force-push；同步上游优先采用一次可审查的 merge，或由全组协调 rebase。

## 完整 skills 与依赖验证

官方仓库已经提供：

```text
.agents/skills -> ../skills
.claude/skills -> ../skills
```

`bootstrap-skills.sh` 以 repo-local Ion 同步官方 `Ion.toml` 管理的远程 skills。验收分层进行：

| 层级 | 验收内容 |
|---|---|
| Discovery | 所有 `SKILL.md` 可读，Agent 链接无断裂，Ion skills 已同步 |
| Core | Git、GitHub CLI、AI Agent、Python、PDF 渲染和仓库测试可用 |
| Training | `/beginner-training` Track 1 通过，Track 2 可启动 |
| Track | 只安装并 smoke test 最终赛道需要的软件栈 |
| Cluster | 仅在挑战需要时验证 SSH、Slurm、rsync、Apptainer 或 GPU |

“功能可用”必须有命令退出码或可复现输出作为证据。仅有 skill 链接不能代表 Julia、集群或 GPU 功能已经通过。

## Claude Code 与 Codex 的启动目录

两个 Agent 都必须把小组 worktree 当作项目根，但无需手动进入目录：

```bash
# 组队后，从 condensed-matter-workspace 任意位置运行
.training/bin/run-codex.sh
.training/bin/run-claude.sh

# 组队前只检查基准 clone
.training/bin/run-codex.sh --base
.training/bin/run-claude.sh --base
```

Codex 官方支持 `-C/--cd`，并从当前工作目录向 Git 根扫描 `.agents/skills` 与 `AGENTS.md`；启动器使用这一接口。Claude Code 启动器先 `cd` 到 worktree，再执行 `claude`，从而加载仓库的 `.claude/skills` 和项目指令。`--add-dir` 只用于额外文件权限，不应替代正确项目根。

从凝聚态工作空间根直接启动 Agent 时，它不会向下扫描被忽略的 `.training/worktrees/...`，因此看不到培训仓库的完整 skills。

## gh、Git 与系统代理

GitHub CLI 没有独立的持久 proxy key，因此使用标准代理环境变量，同时保留 SSH Git 协议：

```text
gh API       -> GNOME HTTPS proxy
gh repo clone
git fetch
git push     -> ssh.github.com:443 -> nc ProxyCommand -> GNOME proxy
```

本机配置：

- `gh config get git_protocol --host github.com` 保持 `ssh`。
- `~/.local/bin/gh` 是 `/usr/bin/gh` 的轻量代理包装器。
- `~/.local/bin/github-ssh-proxy` 动态读取当前 GNOME HTTPS proxy。
- 培训同步脚本在 home 包装器不存在时回退到本机 `.training/bin/` 副本。
- 系统代理关闭时 SSH helper 退回直连。
- `GH_PROXY_BYPASS=1 gh ...` 可为单次命令禁用包装器代理。

该配置已通过 `gh auth status`、GitHub API 查询和 `gh repo clone` 端到端验证。两个 home 脚本仅处理网络，不包含或安装 skill。

## 与个人工作空间的成果交换

培训 PR 是通用、公开、可复现的；个人工作空间是长期、可能私有的。二者只通过显式导入导出交换成果：

```text
group worktree
├── 通用代码、skills、知识卡片 ──> 官方 PR
├── results/ 临时输出             ──> 不提交
└── 值得长期保存的结果            ──> .training/exports/
                                      ├── data/processed/hackathon/
                                      └── notes/
```

禁止培训脚本依赖个人工作空间的绝对路径。私人 PDF、MinerU OCR 中间结果、个人知识库、Obsidian 草稿、SSH 密钥、Token 和集群私有配置不得进入 PR。

## 培训结束后的处理

1. PR 合并后，将主工作空间的官方 `quantum.harness` 子模块更新到包含该 PR 的 upstream commit。
2. 将长期有价值的数值结果复制到 `data/processed/hackathon/`，并记录源 PR、commit、参数与校验信息。
3. 将研究理解整理进 `notes/`；个人 PDF 和 OCR 数据继续遵守个人知识库规范。
4. 保留个人 fork 和小组远程分支作为公开历史；确认所有成果已推送后，才考虑删除本地 worktree。
5. 如果 PR 未合并但改动对个人研究有用，只在工作空间功能分支中引用个人 fork 的明确 commit，不改变 `master` 的官方上游关系。
