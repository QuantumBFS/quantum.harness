## 2. 先把 J 的符号问题说清楚

这是当前最容易出错、也最容易被评审抓住的地方。

### 2.1 两套写法

| 出处 | 哈密顿量 | 铁磁对应 |
|---|---|---|
| Challenge 148 / Blöte–Deng | $H=-J\sum_{\langle ij\rangle}\sigma^z_i\sigma^z_j-h\sum_i\sigma^x_i$ | $J>0$ |
| 我们的 Julia / Xu–Zhang 论文 | $H=+J\sum_{\langle ij\rangle}\sigma^z_i\sigma^z_j-B\sum_i\sigma^z_i-\Gamma\sum_i\sigma^x_i$ | $J<0$ |

括号里的符号不同，仅此而已。**挑战的 $(J=1,\ h)$ 等价于我们代码的 $(J=-1,\ \Gamma=h)$，
物理完全相同，$h_c$ 完全相同。** 之前 C++ stage report 写 "ferromagnetic runs use $J=-1$"
就是这个意思，没有错。

### 2.2 为什么这个符号在本挑战里**必须**盯住

- **蜂窝晶格是二部图**：对 B 子格做 $\sigma^z\to-\sigma^z$ 的幺正变换，
  可把 AFM 变成 FM。所以蜂窝上 $|h_c|$ 与符号无关，写错也看不出来。
- **三角晶格不是二部图**（有三角形，奇圈）：AFM 是**阻挫**的，
  物理完全不同（order-by-disorder、clock 序、完全不同的 $h_c$ 和普适类）。
  三角晶格上**符号写错 = 答案全错**。
- 注意 `docs/三角晶格TFIM_loop算法note.md` 的 benchmark 用的是 $J=+1$，
  即**阻挫 AFM**——那是 Xu–Zhang 论文的目标，**不是本挑战的目标**。
  本挑战三角晶格必须用 $J=-1$（该代码约定下的 FM）。
- 两种符号都**没有符号问题**（$\sigma^z$ 基下横场项给出非正的非对角矩阵元，
  与 $J$ 的符号无关）。所以"无符号问题"不能用来判断符号写对没有。

### 2.3 落实动作

所有新代码的 CLI 一律接受**挑战约定**（$J>0$ 为铁磁），在内部转换。
并加一个断言：三角晶格 + FM 时，$h_c$ 必须落在 4.7–4.8；蜂窝 2.1–2.2。

## 3. 新计划核心：颜色分解并行 Line Update

### 3.1 三种更新的定位

| 更新 | 来源 | 结构 | 并行性 | 纵向场 $B\ne0$ |
|---|---|---|---|---|
| **cluster** | Sandvik 2003 | 全局 cluster，无拒绝 | ✗ 本质串行 | ✗ 失效 |
| **loop（merge–unmerge）** | 课题组，arXiv:2409.17835 | worm 型，虫头在空间移动 | ✗ 串行 | ✓ 可用 |
| **line** | 本科毕设 / `sse_new` | 单格点虚时线段，Metropolis | ✓ **图着色可并行** | ✗ 失效 |

三者共享同一个对角更新和同一套测量。这让 apples-to-apples 比较成为可能——
这本身就是一个别人交不出来的东西。

### 3.2 line update 是什么

对单个格点 $i$：它的虚时世界线被该格点上的**单体算符**切成若干"线段"。
取相邻两个单体算符之间的一段，把这段里 $i$ 的自旋整体翻转。

- 两端的单体算符在 常数 $\Gamma\mathbb{I}$ ↔ 非对角 $\Gamma\sigma^x$ 之间切换
  （权重都是 $\Gamma$，比值为 1，不进接受率）；
- 线段中间遇到的**键算符**只有 $i$ 这一条腿翻转，权重改变；
- 接受概率
  $$
  P=\min\Big(1,\ \prod_{b\in\text{线段}}\frac{w_b(\text{新})}{w_b(\text{旧})}\Big).
  $$

对角更新只插删**常数**单体算符；非对角算符完全由 line update 产生和消灭。
两者合起来保证遍历性。

### 3.3 为什么它能并行，而 cluster 不能

翻转格点 $i$ 的线段，只会读写 $i$ 自己的单体算符、以及 $i$ 的**关联键算符**的腿。
所以两个格点 $i,j$ 能同时更新的充要条件是：**它们不相邻**。

于是"冲突图 = 晶格图本身"，需要的正是一个**正常点着色**：
同色格点两两不相邻 → 同色格点可以全部并行更新 → 按颜色轮流更新即可无冲突。

$$
\text{颜色 }1 \to \text{颜色 }2 \to \cdots \to \text{颜色 }k \to \text{颜色 }1\cdots
$$

毕设里 1D 链用的是奇偶（黑白）分解，就是 $k=2$ 的特例。

### 3.4 本挑战的巧合：正好一个 2 色、一个 3 色

| 晶格 | 二部？ | 色数 | 并行度 | 约束 |
|---|---|---|---|---|
| **蜂窝** | 是（A/B 子格） | **2** | $N/2$ | 无 |
| **三角** | 否（含三角形） | **3** | $N/3$ | 需 $L_x,L_y$ 被 3 整除 |

三角晶格的显式三着色：坐标 $(x,y)$ 取

$$
c(x,y)=(x+2y)\bmod 3 .
$$

验证三个方向的近邻：
$(x{+}1,y)\to c{+}1$；$(x,y{+}1)\to c{+}2$；$(x{-}1,y{+}1)\to c{+}1$。
六个近邻全部异色 ✓。周期边界自洽要求 $L_x\equiv0$、$L_y\equiv0 \pmod 3$。

> 这条 $L\equiv0\ (\mathrm{mod}\ 3)$ 的约束是**真实的物理/算法约束**，
> 要在报告里明说：现有生产尺寸 L=40、64 不满足，L=12/24/48 满足。
> 不满足时退化为基于冲突图的贪心/DSATUR 着色（一般需要 4 色），并行度略降但仍可用。

这正是毕设笔记里写的展望：
> "并行优化的后续方向是把黑白分解推广为三色分解，更新顺序可写成 `123123...`，
> 每次只更新同一种颜色的格点。若更复杂的次近邻结构导致三色不足，
> 则应基于冲突图重新着色。"

**本次工作 = 把这个展望在挑战的真实晶格上做出来并测出来。**

### 3.5 诚实的科学预期

不吹牛。line update 是**局域**更新，临界点附近的自关联时间几乎肯定**比 cluster 差**。
所以正确的比较指标不是"每秒多少 sweep"，而是：

$$
\text{有效样本率}=\frac{1}{\tau_{\rm int}\times t_{\rm sweep}}
\quad(\text{每 CPU-秒}\ \text{和}\ \text{每 wall-秒 各报一次})
$$

可能的结论有三种，**每一种都是有价值的结果**：

1. 并行 line update 在大 $L$ + 多核下 wall-clock 有效样本率**超过** cluster
   → 直接是可用的生产路线，且指出了打破算力墙的方向；
2. 单核输、多核追平 → 说明"再多核就能赢"，给出交叉点的核数，
   这对集群生产是**可执行的结论**；
3. 即使多核也输 → 定量给出 line update 的自关联代价，
   说明为什么 TFIM 的 cluster 更新难以被并行方案取代——
   这是一个负结果，但是**有测量支撑的负结果**，比没做强。

有一个先验的乐观理由值得写进报告：临界点处 $\Gamma$ 很大
（三角 4.768、蜂窝 2.1325），单体算符密度高，线段很短。
粗估线段内平均键算符数 $\approx z/(2\Gamma)$：
三角 $6/(2\times4.768)\approx0.63$，蜂窝 $3/(2\times2.1325)\approx0.70$。
即**平均每条线只跨约 0.6–0.7 个键算符**，接受率应为 $O(1)$，不会灾难性地小。
