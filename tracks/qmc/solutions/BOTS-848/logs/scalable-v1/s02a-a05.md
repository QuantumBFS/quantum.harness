## A05.1 contract and implementation

The tests-only commit specifies the runtime `StateHandle`,
`CandidateAdapter`, and `DiagnosticProvider` contracts; ordered multiplet keys
`(-2, -1, 0, 1, 2)`; checkpoint, optimizer, training-log, protocol, seed,
manifest, and source-file identity; tamper rejection; and the sole factory
input `BOTS848_SCALABLE_RUN_DIR`.  Capacity-changing runtime overrides are not
accepted.

`OccupationState` exposes batched sample, logpsi, sparse local-energy, and
local-L2 operations.  `OccupationCandidate` exposes the frozen ground state,
all five derived spin-two tower components, the exact construction
certificates, diagnostic provider, and measured resource record.  The factory
strictly parses and validates the terminal artifacts before reconstructing a
candidate.  It rejects duplicate JSON keys, nonstandard `NaN`/`Infinity`
tokens, finite-overflow JSON numbers such as `1e9999`, type aliases in resource
fields, source or artifact tampering, and protocol/seed/selection mismatches.

The no-training N=8 mode uses `N=8`, `2Q=21`, seed `4848`, batch `256`, two
warmups, and five measured repetitions.  It exercises support construction,
model sampling/logpsi, sparse energy and L2, tower evaluation, and adapter
batching.  It performs zero optimizer updates and propagates an internally
written `failed` status to CLI exit code `1`.
