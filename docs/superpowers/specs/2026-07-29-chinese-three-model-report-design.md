# Chinese Three-Model Central-Charge Report Design

Date: 2026-07-29

Team: 卧龙凤雏

Challenge: Quantum Harness #122

## Objective

Create a complete Simplified Chinese edition of the existing detailed
three-model central-charge report. The Chinese HTML and PDF must coexist with
the verified English artifacts, use the same frozen numerical evidence, and
localize all reader-facing prose and graphics without changing executable code
or bibliographic facts.

This first Chinese edition uses the currently verified Nishimori widths
`L = 4, 6, 8, 10, 12, 14`. It must not imply that the proposed larger-width
experiment has already run. When that experiment is completed later, the same
shared build path will be used to update both languages.

## Chosen Approach

Use one shared numerical and rendering pipeline with separate English and
Chinese content models.

- Keep the existing English content model and output paths intact.
- Add a Chinese content model that uses the same typed report blocks and
  source-derived numerical values.
- Parameterize the build entry point by language.
- Generate localized comparison plots from the same numeric arrays.
- Make renderer chrome and PDF metadata locale-aware.

This approach was selected over copying the complete report package, which
would duplicate logic, and over a single large translation dictionary, which
would make a long technical report difficult to author and review in context.

## Deliverables

The existing English artifacts remain:

- `output/html/three-model-central-charge-report.html`
- `output/pdf/three-model-central-charge-report.pdf`

The new Chinese artifacts are:

- `output/html/three-model-central-charge-report-zh.html`
- `output/pdf/three-model-central-charge-report-zh.pdf`

The Chinese HTML is self-contained. Both Chinese artifacts are reproducibly
generated by the integrated-report package and are verified before replacing
their destination files.

## Architecture and Data Flow

`analysis/sources.py` remains the sole loader for the three frozen model result
sets. A build loads the results once, records their provenance fingerprint, and
passes the same `ModelResult` objects to the selected content and plotting
functions.

The build command accepts:

- `--language en` for the current English behavior;
- `--language zh` for the Chinese artifacts;
- `--language all` for both editions.

The default remains `en` for backward compatibility. Each locale receives its
own generated-plot directory so localized images cannot overwrite the other
edition. Before publishing any artifact, the build rechecks the source
fingerprint and runs locale-specific verification. Temporary files are removed
on failure.

The report block dataclasses remain format-independent and shared. The Chinese
content model is a separate module so complete paragraphs, captions, and table
notes stay readable in context. Renderers receive explicit locale metadata for
document language, visible labels, numbering, headers, footers, and PDF
metadata.

## Chinese Content

The Chinese edition retains the English report's eleven-section structure,
equations, tables, figures, references, and technical depth. It remains written
for university students and covers:

- the physical meaning of central and effective central charge;
- the three estimators and why each is appropriate;
- Rust Monte Carlo or trajectory implementation principles;
- Python-only data processing and plotting;
- parameter choices and parameter meanings;
- statistical and systematic error analysis;
- model-specific validation gates;
- cross-model comparison and limitations.

All prose uses Simplified Chinese. On first use, important specialist terms
include their English form or standard abbreviation, for example “有效中心荷
(effective central charge, `c_eff`)”. Proper names such as Nishimori, Majorana,
and Wolff retain their Latin spelling and receive a Chinese explanation.

Rust and Python code, identifiers, paths, and shell commands stay unchanged so
they remain executable and traceable to repository sources. Code-listing
titles and explanatory text are translated. Formal paper titles, journal
names, volumes, pages, and other bibliography fields remain in their published
form; surrounding citation guidance is Chinese.

All reader-facing plot text is Chinese, including titles, axes, legends, and
annotations. Figure captions and alternative text are also Chinese.

## Typography and Layout

The HTML root uses `lang="zh-CN"` and a robust Chinese system-font stack.
Existing responsive behavior and self-contained asset embedding remain.

The PDF renderer registers a usable CJK font for every prose-bearing style:
title, subtitle, body, headings, tables, captions, callouts, headers, and
footers. It must fail clearly if no suitable font is available rather than
silently emit missing-glyph boxes. The plotting layer uses the same explicit
CJK-font discovery strategy and preserves mathematical symbols, subscripts,
and minus signs.

The A4 visual system remains recognizable, but Chinese line spacing, heading
wrapping, and table column widths are tuned independently. The Chinese report
is not required to match the English report's page count.

## Localization Rules

Visible fixed labels are locale data, including:

- contents and abstract labels;
- section kickers;
- figure and table prefixes;
- result and warning callouts;
- page headers and footers;
- chart labels and annotations;
- verification-required section names.

Scientific symbols, formulas, numeric precision, confidence-interval bounds,
seeds, widths, step counts, and runtimes are not translated or rounded
differently. Model names may have Chinese descriptive wording, but their stable
internal slugs remain unchanged.

The current Nishimori chapter explicitly states that its evidence covers
`L = 4, 6, 8, 10, 12, 14`. It describes larger widths only as future work, if
mentioned at all.

## Error Handling and Publication Safety

The following conditions abort a locale build:

- a frozen source artifact is missing or malformed;
- the source fingerprint changes during generation;
- no usable CJK font can be registered;
- a localized plot fails to render;
- a required Chinese section, label, or artifact is absent;
- numerical values in the rendered report disagree with source data;
- the HTML or PDF verifier fails.

Artifacts are rendered to locale-specific temporary paths and atomically moved
only after verification. A failed Chinese build cannot modify either English
artifact.

## Verification Strategy

### Data consistency

Tests compare all three displayed estimates, standard errors, confidence
intervals, targets, key parameters, and provenance values against
`ModelResult`. The Chinese report must use the exact frozen data used by the
English report.

### Content completeness

Tests require all eleven Chinese section titles, all report block categories,
Chinese table and figure numbering, Chinese contents labels, and the declared
current Nishimori width set. They also check that renderer chrome does not
retain labels such as `Contents`, `Figure`, `Table`, or `Section`.

Bibliographic titles and executable code are exempt from broad English-text
absence checks.

### Regression and coexistence

All current English tests continue to pass. New tests cover:

- Chinese report-model construction;
- `zh-CN` HTML metadata;
- locale-specific output names and plot directories;
- CJK text extraction from the PDF;
- `en`, `zh`, and `all` build modes;
- preservation of existing English outputs during a Chinese build;
- deterministic builds from unchanged inputs.

### Visual quality

Render every Chinese PDF page to an image and inspect for missing glyphs,
clipping, table overflow, orphaned headings, unintended blank pages, and poor
line breaks. Inspect the self-contained HTML at desktop and narrow viewport
sizes, including its contents navigation and all embedded figures.

Record final page count, embedded-image count, verification results, and
SHA-256 hashes for handoff.

## Acceptance Criteria

The work is complete when:

1. The English HTML and PDF still build and pass their existing tests.
2. The two Chinese artifacts exist at the specified `-zh` paths.
3. All reader-facing report and plot text is Simplified Chinese, subject to the
   explicit code, symbol, proper-name, and bibliography exceptions.
4. The Chinese artifacts reproduce the current frozen numerical results and
   Nishimori width range exactly.
5. Automated source, model, renderer, coexistence, and deterministic-build
   checks pass.
6. Full PDF and representative responsive HTML visual inspection finds no
   missing glyphs, overlap, clipping, overflow, or broken navigation.

## Out of Scope

- Running additional Nishimori Monte Carlo widths or increasing Monte Carlo
  steps.
- Changing any scientific estimate, uncertainty interval, or acceptance gate.
- Rewriting executable Rust or Python examples into translated pseudocode.
- Replacing or deleting the English artifacts.
- Creating a mixed bilingual document; the two editions are separate files.
